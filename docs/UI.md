# Shunt UI

Реализация утверждённого макета без сборки: существующий `index.html`, `ui.css`, `ui-model.js` и `ui.js`. Никаких npm, бандлеров, CDN, веб-шрифтов или новых runtime-зависимостей. Python API и упаковка не изменены: существующий механизм копирует всю директорию static.

## Навигация

| Раздел | Вкладки |
| --- | --- |
| Обзор | Карта разделения соединений, текущий профиль, выход и найденные назначения |
| Маршрутизация | Списки (гео-базы, подписки), ручные правила, найдено проверкой |
| Выходы | Активный выход, VPN серверы, Proxy |
| Домашняя сеть | Устройства и группы, DNS и защита, входящий доступ, подключение роутера |
| Диагностика | Сетевой тракт, аналитика, логи |
| Система | Ресурсы, обновления, автоматизация (планировщик, уведомления), настройки и терминал |

Старые прямые ссылки сохранены. Канонические ссылки имеют вид `#routing/rules`. Работают Back/Forward; старый `#profile` открывает диалог профиля. На телефоне нижняя навигация и меню «Ещё» открывают все шесть разделов.

Существующие формы и обработчики переиспользованы. Ручные правила собраны в таблицу с поиском, фильтрами и явным сохранением. Несохранённые правила и выбранный профиль сохраняются при переходах между разделами; обновление статуса не сбрасывает выбор профиля. Браузер предупреждает при закрытии вкладки с черновиком.

## Данные

- Графика показывает доли **соединений**, не объём переданных байтов; данные из `/api/analytics/summary?hours=24`. Заблокированные и прочие соединения указываются отдельно, знаменатель не подменяется суммой direct + vpn.
- Состояние, применённый профиль, LAN и активный выход берутся из `/api/status`. Активный FPTN имеет приоритет над настройкой AdGuard при отображении выхода.
- WAN берётся из `wan.ip` ответа `/api/network/wan-status`. API не возвращает префикс подсети, поэтому интерфейс не приписывает `/19`.
- Гео-базы показывают размер файлов и дату из `/api/geo-info`. Число доменов и адресов не подставляется из статического брифа.
- Счётчики обнаружения показывают все записи и направленные в туннель. Отсутствие маршрута не объявляется ожиданием второго подтверждения.
- Uptime не выводится: в используемом API его нет. В боковой панели показан адрес шлюза.
- Новое обновление обзора выполняется раз в 30 секунд только на открытом обзоре в видимой вкладке. При выходе остановлены таймеры и потоки; отложенные повторные подключения также отменяются.

## Проверки

```sh
python3 -m pytest tests/ -q
node --test tests/ui-model.test.cjs
python3 tests/ui_fixture.py --port 8766
```

Node нужен только для запуска пяти тестов модели; интерфейс запускается без него. Локальный стенд использует только стандартную библиотеку Python, слушает исключительно `127.0.0.1` и помечает страницу «ТЕСТОВЫЕ ДАННЫЕ». Он не запускает код шлюза и не меняет сетевые настройки. Его упрощённые ответы предназначены для проверки UI, а не для имитации всех сервисов.

Проверено 14 сентября 2026:

- 478 Python-тестов и 5 JS-тестов проходят. Четыре существовавших предупреждения FastAPI о `on_event` остаются.
- Синтаксис всех inline-скриптов и новых JS-файлов проверен Node.
- Все подключаемые runtime-ресурсы локальны и присутствуют; адаптер UI загружается до проверки авторизации.
- В браузере открыты 22 страницы деталей по прежним hash-ссылкам, отдельно проверен обзор; ошибок JavaScript при этом не зарегистрировано.
- Сравнение DOM со старой страницей: сохранены все ID элементов управления, кроме трёх удалённых элементов навигации (`nav-showall`, `nav-showall-label`, `nav-terminal`). Повторяющихся ID нет.
- Визуально проверены обзор в светлой и тёмной теме на 1440×900 и 390×844, маршрутизация на десктопе, правила и меню на телефоне. Проверены русский и английский языки; новые подписи добавлены в существующий словарь.
- Через браузер добавлено и сохранено тестовое правило; сохранение подтверждено чтением состояния fixture API. Проверено сохранение черновика при переходе на обзор и обратно.
- Проверены выбор профиля, его сохранность после фонового обновления статуса и применение через существующий POST.
- Проверены диалог профиля, тест маршрута, Back/Forward, выход, прекращение API-запросов после выхода и повторный вход.
- Проверены HTTP 503 для статуса и недоступная статистика: предупреждение, отсутствие зелёного статуса, прочерки вместо счётчиков.

## Граница проверки

Интерфейс включён в пакет Shunt 2.20.0. На домашний шлюз в рамках этого выпуска он не устанавливался. Реальная смена туннеля, DNS, сетевых правил, обновление сервисов и терминальная WebSocket-сессия требуют проверки на самом шлюзе. Их существующие обработчики сохранены; успешная работа локального стенда не доказывает поведение сетевых сервисов.

## Проверка пакета

После тестов выполнена сборка `packaging/build.sh` и проверка:

```sh
python3 tests/verify_package.py dist/shunt_2.20.0_all.deb
```

Проверяются версия, архитектура `all`, совпадение Python-кода и static с исходниками, все MD5-суммы, покрытие файлов суммами либо conffiles, владелец root, права исполняемых файлов, синтаксис установочных скриптов и Python, отсутствие кешей. Рядом с пакетом создаются SHA256SUMS и package-checks.json. Проверка не устанавливает пакет и не запускает сетевые службы.

На macOS упаковщику нужны Homebrew dpkg и GNU coreutils/findutils/grep/tar с их `gnubin` в PATH. На Debian используется штатный dpkg-dev. Это упаковка готовых статических файлов, а не сборка фронтенда.
